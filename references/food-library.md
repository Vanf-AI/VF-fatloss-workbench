# 食材库（foodLibrary）与别名维护

前端食材分「内置库 + 自定义层」两层，统一由 `allFoods()` 合并为最终可选的食材集合。改动用私有云持久化，内置库本身只读。

## 数据模型（FatLossPack.foodLibrary）

- `selected[]`：历史遗留（早期「选食材」用），现已弃用，保留空数组向后兼容。
- `hidden[]`：隐藏的内置食材 `id` 数组；隐藏后不参与选择与记录。
- `custom[]`：自定义 / 覆盖条目数组。每项：
  - `id`：命中内置同 `id` = 覆盖该内置；否则视为纯新增（`custom-*`）。
  - `name`、`carb` / `protein` / `fat`：名称与宏量（克，按 `per` 口径）。
  - `unit`：`g` / `ml` / `个`；`per`：基准量（100=每 100g/ml，1=每 1 个）。记录时按 `amount / per` 折算宏量。
  - `category`：6 类之一或内置细分；覆盖内置时保持内置原分类。

## 内置库（fooddb.json）

只读基准，公开文件。保留 7 类细分：主食 / 肉类蛋白 / 蛋奶 / 蔬菜 / 水果 / 坚果 / 其他（**不改**）。前端归一映射为 6 类展示与筛选。

## 6 类归一

```text
FOOD_TYPES = ["主食", "蛋白质", "脂肪", "水果", "蔬菜", "其他"]
FOOD_TYPE_MAP = {
  主食→主食, 肉类蛋白→蛋白质, 蛋奶→蛋白质, 坚果→脂肪,
  蔬菜→蔬菜, 水果→水果, 其他→其他, 自定义→其他
}
```

归一函数 `foodType(f)`：先查 `FOOD_TYPE_MAP[f.category]`，命中直接返回；否则若 `f.category` 本身已是 6 类之一则原样返回，否则归「其他」。

## 别名维护（FOOD_ALIASES）

周餐单同步到今日时，按食材名匹配录入库 `id`。配餐口径名（如「鸡琵琶腿（去皮）」「燕麦」「全蛋」「大米（生）」「烹调油」「龙利鱼」）与 fooddb 条目名不一致时，必须在 `app.mjs` 的 `FOOD_ALIASES` 里补别名，否则宏量记 0。

**纪律**：凡新增食材名（无论是周餐单、配餐还是示例），都要确认别名或归一，保证名能命中 `id`；回填 / 改餐单后做一次「同步今日」冒烟，抽查每个食材都记到非零宏量。
