# 复盘规则

每 7 天综合一次，结果写入 `goal`（新目标）与 `reviews[]`。只使用已确认的体重趋势，不用单日体重下判断。

复盘有两条等价路径，**共用同一套口径，结论必须一致**：

1. **工作台内置引擎（推荐，确定性）**：前端 `computeReview()` 按本文规则自动判定并在「复盘」页展示，用户点「确认并生效」才写入。不调用大模型。
2. **对话内复盘（补充）**：需要结合体型照、主观感受、训练细节时，由 Agent 按本文规则给结论，再写回 `goal` / `reviews[]`。

## 核算窗口

取最近 **7 个有体重记录的日期**（不足 7 天就用现有全部），而不是自然日切片——漏记几天不会让窗口整体落空。

降幅按实际跨度折算成「每周降幅%」：

```text
weeklyDropPct = (首日体重 − 末日体重) / 首日体重 × 100 × 7 / 跨度天数
```

窗口内同时统计：`hunger`（1–5）、`trainingFeel`（有力 / 一般 / 乏力）、`sleep`、以及由 `meals` 算出的宏量偏差。

## 阈值（必须与前端实现一致）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `TARGET_DROP_PCT` | 1.0 | 每周理想降幅；低于此值判定偏慢 |
| `FAST_DROP_PCT` | 1.5 | 周降幅超过此值判定过快，触发保护性加碳水 |
| `STAGE_RESET_PCT` | 3.0 | 阶段累计降幅达到此值 → 按新体重全量重算 |

## 判定顺序：生活化减脂 / 碳水循环

按优先级**自上而下取第一条命中**，不叠加——这就是「同次碳水调整不叠加」的实现方式。

1. 周降幅 > 1.5% → 碳水 **+30g**（优先保可持续性）
2. 窗口内出现饥饿感 5 → 碳水 **+30g**
3. 饥饿感 ≥4 达 ≥2 天 → 碳水 **+10g**
4. `trainingFeel = 乏力` 达 ≥2 次 → 碳水 **+10g**
5. 周降幅 < 1.0% → 碳水 **−10g**
6. 其余（落在 1.0%–1.5% 之间）→ 保持当前目标

> 方向性提醒：这一组的逻辑是「饿了 / 掉太快 → 加碳水」。与增肌减脂并行**方向相反**，不可混用。

## 判定顺序：增肌减脂并行

以状态信号为主，不机械按百分比：

1. `乏力` ≥2 次，或睡眠均值 < 6.5h → 碳水 **−10g**（先减负担，并回看睡眠与有氧量）
2. 饥饿感 ≥4 达 ≥3 天 **且** `有力` ≥2 次 → 碳水 **+10g**
3. 饥饿感平均值 ≤2（胃口差 / 偏饱）→ 碳水 **−10g**
4. 其余 → 维持当前目标与缺口

## 阶段全量重算

```text
阶段累计降幅 = (stageBaselineWeight − 当前体重) / stageBaselineWeight × 100
```

达到 3% 时**优先于**上面的单点调整：

- 按新体重与方法口径重算碳蛋脂：生活化减脂查系数表；碳水循环用当前阶段系数；增肌减脂并用 `startPoint`。
- 重算后把 `goal.stageBaselineWeight` 更新为当前体重，阶段重新起算。
- 方法参数缺失（如 `method.phases` / `method.startPoint` 未提供）时**不做自动重算**，提示回对话中重算，避免套错系数。

## 输出与闸门

- **`goal`**：`carb / protein / fat / kcal` 覆盖为新目标；同时维护 `reviewDay`、`stageBaselineWeight`、`adjustLog`。
- **`reviews[]`**：`{ day, windowStart, windowEnd, message, nextGoal, confirmed, confirmedAt }`；`message` 说明判定依据。
- **`goal.adjustLog[]`**：`{ at, windowStart, windowEnd, verdict, deltaCarb, stageReset }`。**同一 `windowEnd` 已存在记录时禁止再次应用**——这是「同次不叠加」的第二道闸门，防止用户重复点击造成碳水连续下调。
- **未确认不得覆盖 `goal`**。
- **归档**：复盘摘要同步写入 `history.reviews[]`；被替换的 `weeklyPlan` 归档到 `history.weeks[]`（只读、不重算）。

## 下一阶段餐单

复盘只产出**目标数字**。要得到下一阶段的 7 天餐单，由工作台「下一阶段餐单」卡调用云端大模型，按 `nextGoal` + 食材库生成，通过结构校验后由用户点「应用到本周计划」写入。生成契约见 [planning.md](planning.md)。
