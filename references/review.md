# 周复盘规则

每 7 天（每周 `reviewDay`）综合一次，结果写入 `reviews[]` 与 `goal` 的 `nextGoal`。只使用已确认的 D1 与 D7 体重趋势，不用单日体重下判断。

## 输入
- `logs` 中本周每天的 `weight` / `sleep` / `training` / `hunger`。
- 当前 `goal` 与阶段基准体重 `stageBaselineWeight`。
- **执行偏差（deviation）自动计算**：前端 `computeDeviations` 遍历每日 `meals` 的宏量快照求和（`dayIntake`），与 `goal` 逐项对比得出 `dCarb / dProtein / dFat` 及偏差率；判定规则——任一项 >+10% 记「超量」、任一项 <−10% 记「不足」、否则「达标」。用户无需手动填写偏差。

## 生活化减脂 / 碳水循环 的调整
- 平均每 7 天下降约 1%：保持当前目标。
- 下降过快或本周饥饿感 5：碳水 +30g（优先保障可持续性）。
- 至少 2 天饥饿感 4：碳水 +10g。
- 至少 2 次训练记录表现下降：碳水 +10g。
- 平均每 7 天下降 <1%：碳水 −10g。
- 阶段体重降 ≥3%：按当前体重全量重算碳蛋脂。
- 同次碳水调整不叠加。

## 增肌减脂并行 的调整
- 以 `stateSignals`（渴望 / 训练状态 / 睡眠 / 食欲）为主，不机械按百分比。
- 有明显渴望且训练 / 精神良好：碳水小幅上调，蛋白略降。
- 胃口下降 / 吃撑：碳水下调，蛋白略升。
- 脂肪维持在 `ranges` 内；目标维持轻微饥饿但不影响训练 / 精神 / 睡眠。
- 同样遵循阶段降 ≥3% 才全量重算。

## 输出
- `reviews[]`：`{ day, message, nextGoal, confirmed }`；`message` 说明依据。
- 用户确认后把 `nextGoal` 写入下一周 `goal`；未确认不得覆盖。
- 归档已完成周到 `history.weeks[]`（只读不重算）。
